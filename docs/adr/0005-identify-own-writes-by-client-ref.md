# 复查按 client_ref 识别本任务自己的写入

业务服务的查询结果在两种幂等模式下都带回写入时提交的客户端参考号，也就是操作标识。`assess` 把客户端参考号属于本任务操作标识集合的记录认作本任务自己的写入，不把它们当作冲突申请。此前，识别自己的写入依赖"先核验、后复查"的顺序。原型表明，这样一来"去掉核验"消融组会把自己响应丢失的那张售后单误判为冲突，向顾客报告失败，而售后单其实已经创建。这个组测到的就不只是"不核验"的效果。改用客户端参考号后，正确性不再依赖顺序，消融只测量核验本身。"先核验、后复查"的顺序仍然保留，因为它代价很小，而且让恢复过程更好解释。

本决定修改了 ADR 0004 的一个前提：复查的正确性不再依赖它排在核验之后。
