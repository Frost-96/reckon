# 售后规则是易变读，运费进入确认参数

"查询售后规则"按易变读标注，它返回的退货运费进入"提交退货"的规范化参数，从而进入确认哈希。写请求携带用户确认过的运费；业务服务的"校验运费"开关开启时（默认开启），运费与当前值不一致即返回 `FEE_CHANGED` 拒绝。spec 原本把售后规则标为稳定。原型矩阵表明，那样一来故障期间运费变化时，复查不会重新执行这个读，除故障即转人工组外的所有组都用旧运费完成了写入，也就是基于失效条件的写入。改为易变后，复查能发现运费变化，`assess` 给出"重新确认"；写操作已处于 SENT 时也同样成立。业务服务的运费校验是第二道防线：没有复查的组（轮次级重跑、去掉复查）从失效写入变为被拒绝。因此"去掉复查"消融按开关分两种口径：开关关闭时，复查是运费变化的唯一防线，消融测的是失效写入；开关开启时，复查的贡献体现为终态类别是否正确。创建售后单生效之后的运费变化映射为"继续"，因为已提交的售后单不受影响。

本决定修改了 spec 中"查询售后规则（稳定）"的标注，与 ADR 0004 的"复查只重跑易变读"相配合。
